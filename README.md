# Отчёт по авансам и оплате работ

Программа строит отчёт по каждой работе и договору на указанную дату: цена, выплачено, осталось оплатить. Общий аванс распределяется расчётно по принятым работам после учёта целевых платежей. Описание входных CSV — `data/FORMAT.md`, допущения — `DECISIONS.md`.
Решение работает локально, ничего не отправляет во внешние сервисы. Python 3.10+; сторонних Python-пакетов нет.
Команды выполняются из папки решения. На Windows вместо `python3` можно использовать `py -3`.

## Быстрый запуск интерфейса

```sh
python3 report.py --serve
```

Откройте http://127.0.0.1:8000. Выберите дату и нажмите «Построить отчёт».
Работы раскрываются по каждому договору. Кнопки CSV скачивают таблицы на дату показанного отчёта.
Готовый `frontend/dist/` включён: Node.js для запуска не нужен.
Остановка сервера — Ctrl+C. При занятом порте укажите `--port 8001`.

## CLI

```sh
python3 report.py --data-dir data --date 2026-11-10 --out-dir output
```

Создаёт `works.csv`, `contracts.csv`, `allocations.csv` и `report.json`.
CLI и HTTP используют один расчётный модуль `accounting.py`.
Дата обязательна для CLI; формат YYYY-MM-DD, события в этот день включаются.
Деньги в CSV и JSON — рубли с двумя знаками, в расчёте — целые копейки, без float.
CSV: UTF-8 с BOM, разделитель запятая, десятичная точка. Если Excel не разделил колонки автоматически, импортируйте CSV с этими настройками.
Повторный запуск CLI перезаписывает файлы в указанной выходной папке. Перезапись исходных CSV запрещена: папка вывода должна отличаться от папки входных данных.

## Своя папка данных

```sh
python3 report.py --serve --data-dir "/полный/путь/к/data"
```

В папке должны быть `contracts.csv`, `works.csv`, `payments.csv` с колонками из FORMAT.md.
Без `--data-dir` используется папка `data/` рядом с программой, независимо от рабочей директории.
Каждый запрос заново читает файлы. Не изменяйте CSV во время формирования отчёта: атомарная выгрузка трёх файлов не реализована.
HTTP доступен только через loopback, без загрузки файлов, записи данных и публичного хостинга.

## Колонки и сверка

Все таблицы содержат `as_of` и `contract_id`.

| Таблица | Колонки |
|---|---|
| works | `work_id`, `title`, `status` на дату; `price` — исходная цена; `paid` — целевые и распределённые выплаты за вычетом возвратов; `remaining` — непокрытая стоимость; `excess` — целевой излишек |
| contracts | `contractor`; `amount` — исходная сумма; `active_price` — цена неотменённых работ; `discrepancy` = amount − active_price |
| contracts | `gross_paid` — отправлено; `refunded` — возвращено; `net_paid` — чистая выплата; `work_paid` — отнесено на работы; `unallocated` — свободный общий аванс |
| contracts | `remaining` — сумма остатков работ; `funding_needed` — max(remaining − unallocated, 0); `excess` — целевые излишки; `contract_balance` = amount − net_paid |
| allocations | `payment_id`, `work_id`, `amount`, `kind`: direct — явная привязка; allocated — расчётное распределение; unallocated — свободный остаток, work_id пуст |

Возвращённые к дате платежи отсутствуют в allocations; их сумма отражена в refunded. Очередь и будущие платежи не входят в выплаты.
В `report.json` дополнительно есть предупреждения; они также выводятся CLI и интерфейсом.

Инварианты: `net_paid = gross_paid − refunded = work_paid + unallocated = сумма allocations` в пределах договора.
Целевой излишек не считается свободным авансом и не уменьшает автоматически остатки других работ.
Баланс от исходной суммы договора не является требованием перечислить деньги: при отменах он отличается от потребности по действующим работам.

## Проверки и пересборка

```sh
python3 -m unittest discover -s tests -v
```

Для изменения интерфейса: Node.js 24 и pnpm 11.25.0.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

Сборка проверяет типы TypeScript и создаёт `dist/`. После неё перезапустите Python при необходимости и обновите страницу.
Библиотеки интерфейса не загружаются из CDN. TypeScript не выполняет денежную арифметику.

## Сдача и ограничения

- `DECISIONS.md` — допущения и последствия альтернатив.
- Транскрипт Codex передаётся отдельным архивом вместе с кодом, не хранится в Git. Это экспорт доступных пользовательских сообщений и вызовов инструментов из локального журнала, не официальный `/export` Claude Code. Исходно усечённый инструментами вывод не восстанавливается.
- Исходных данных достаточно для восстановления дат оплаты/возврата/приёмки/отмены, но нет истории изменения цены, состава работ и суммы договора. Подробнее в решениях.
- Это небольшой локальный инструмент; многопользовательская работа, журнал проводок и редактирование данных не входят в задачу.
- Не публикуйте задание, данные или решение. Передавать архивом либо приватным репозиторием.

По согласованию с кандидатом работа выполнена в Codex, а вместо экспорта Claude Code требуется транскрипт Codex. Интерфейс добавлен по запросу кандидата.

Функциональные требования реализованы. Интерфейс добавлен по отдельному запросу и не требуется для запуска CLI. Перед сдачей прикладывайте оба архива — код и транскрипт.
